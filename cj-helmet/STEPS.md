# CJ-Helmet: как это придумалось и делалось

История по шагам: идея, версии прошивки (v1-v4) и приложения (shlem1-shlem5), что меняли
и почему, и что впереди. Метки `cj-*` в репозитории отмечают конец крупных шагов.

## Итерация 0. Идея (23.10.2026)

Задача СиДжея: есть шлем, есть светодиоды - пусть шлем показывает торможение, разгон и
поворот по данным моноколеса Sherman L, по примеру WheelLog.

- Протокол колеса разобрали по исходнику WheelLog (`VeteranAdapter`): Bluetooth-сервис
  FFE0/FFE1, пакет с заголовком `DC 5A 5C`, скорость, ток, наклон, напряжение, PWM.
- Первый вариант - плата ESP32 подключается к колесу напрямую. Отказались: колесо держит
  одно Bluetooth-соединение, и тогда WheelLog на телефоне не работает.
- Выбрали **телефон как мост**: колесо -> телефон (форк WheelLog) -> плата в шлеме. Android
  спокойно держит два соединения.
- Плата: сначала примеряли ESP32-ETH01 (крупная, без USB), для шлема взяли
  **nanoESP32-C6** - USB, BLE 5, ESP-NOW. Написано ТЗ, работа ушла на домашний сервер
  (MiniGUN) - там плата по USB, Bluetooth и сборка.

## Прошивка v1 - шлем знает режимы (23.10)

- Свой протокол BLE телефон -> шлем: пакет данных колеса и настройки (config).
- Режимы: габарит, стоп, разгон, «нет связи» (тишина больше секунды - нейтральный свет,
  последний стоп не держим).
- Десять проверок по Bluetooth с сервера прошли: кочка не даёт стоп, неверные пакеты и
  неверные настройки отбрасываются, порог из настроек действует.
- Лента WS2812 COB, около 135 точек, кольцом по краю HJC RPHA 70 Carbon.

## Прошивка v2 - пороги по живой езде (23.10)

Взяли логи WheelLog за две поездки, около 55 минут:
- колесо шлёт 5 пакетов в секунду без выбросов - сглаживание медианой убрали, оно
  добавляло задержку;
- ток WheelLog отдаёт по модулю - стоп по току выключили;
- наклон колеса опережает скорость: при торможении он ловит стоп примерно на 0,7 с раньше.

Итог: **стоп** - от замедления 5 км/ч в секунду или от наклона назад на 2,5° сверх среднего
за 8 секунд. По логам это 3-5 стопов в минуту.

## Прошивка v3 - обновление по воздуху (24.10)

- Если телефона нет дольше 30 секунд, шлем уходит в домашний Wi-Fi и принимает новую
  прошивку по воздуху (ArduinoOTA с паролем).
- Тип ленты в настройках (GRB, RGB, BRG, GRBW, RGBW); старые настройки переносятся сами.

## Приложение shlem1-shlem3 - шлем в WheelLog (23-24.10) - `cj-1-shlem`

- **shlem1**: модуль «Шлем» - своё соединение со шлемом, колесо WheelLog не трогаем;
  экран настроек под складной телефон (от 600 dp - две колонки); своё имя пакета, ставится
  рядом с WheelLog из Play. Синхронизацию с electro.club отключили: ключ к ней есть только
  в официальной сборке, а чужой ключ брать нельзя - треки выгружаются CSV вручную.
- **shlem2**: кнопка шлема в верхней строке вместо часов: серая - выключено, белая - нет
  связи, зелёная - на связи.
- **shlem3**: ползунки порогов без отметок шагов.

**Первый выезд с телефоном (24.10):** связь и передача работают - 4416 пакетов, настройки
пишутся. Но «горят две точки»: зоны ленты задавались ползунками, и на стоп сзади выпадало
две точки. Отсюда следующая версия.

## Прошивка v4 и раздел «Подсветка» - сегменты, роли, колесо (24.10) - `cj-2-svet-koleso`

- **Сегменты вместо зон**: лента - одна цепочка, поделённая на куски с ролями: перед,
  бока, зад, козырёк, педали, обод. Предупреждение, если на стоп меньше 5 точек.
- **Роли платы**: «шлем» или «колесо». Шлем пересылает режим колесу по ESP-NOW
  5 раз в секунду, колесо может светиться и без своего телефона.
- **Пакет v2**: PWM и заряд колеса - режим «предупреждение» при высоком PWM.
- Проверка без езды: каждый режим включается кнопкой в приложении, на экране шлем
  показывает ленту потоком кадров.
- Приложение: раздел **«Подсветка»** вместо «Часов» - шлемы и колесо одним списком, у
  каждого свой вид (интеграл или мотокросс) и сегменты.

## Приложение shlem4 - второй шлем со штатным контроллером (24.10) - `cj-3-zengge`

- Второй шлем, LS2 Subverter EVO, со штатным Bluetooth-контроллером **ZENGGE**
  (LEDnetWF): телефон красит всю ленту - стоп красным, разгон своим цветом, поворот жёлтым.
- Нашли, почему ZENGGE молчал: телефон держал связь только с «активным» шлемом. Теперь
  подключается ко всем устройствам, где стоит галка.
- Для шлема без платы пороги считает сам телефон.

## Провод к колесу (24.10, вечер) - `cj-4-provod`

- Внутри Sherman L нашли Bluetooth-модуль колеса (ZS-040, CC2541) на плате контроллера.
  Плата CJ **слушает только его RXD** - то, что колесо отправляет в модуль (115200 8N1).
  Колесу ничего не пишем.
- Свет работает без телефона: стоп и разгон на ленте СиДжей видел при живом колесе.
- Из пакета по проводу берутся PWM и заряд.
- Мост USB-UART для проверки модуля; мощность модуля поднята (связь в металлическом
  корпусе колеса слабая).

## Приложение shlem5 - своё лицо и GitHub (25.10) - `cj-5-v1`

- Своя иконка: шлем с лентой стоп-сигнала на тёмном фоне - не путать с WheelLog.
- Форк на GitHub, сборка APK в GitHub Actions, страница проекта.
- Кнопок поворотника не делаем: свет включает само колесо. Прошивка их понимает -
  вариант для тех, у кого нет телеметрии колеса.

## Плата в колесе по проводу (25.10)

- Платы ESP32-C3 SuperMini прошиты (`c3-mini`): лента GPIO10, светодиод GPIO8. Одна C3 - в
  шлем LS2.
- В колесо пошла nanoESP32-C6: место есть, антенна лучше. Читает данные колеса с линии RXD
  Bluetooth-модуля, GPIO20 через 1 кОм.
- Проводов к плате четыре: +5 В и минус от понижайки LM2596, RXD модуля, земля модуля.
  Земля модуля обязательна: минус понижайки с землёй колеса не связан, без неё ни одного байта.
- Проверено на колесе: 115200, 5 пакетов в секунду, битых 0, напряжение 147 В, заряд 96%.
- Питание света - от разъёма «Power Supply Module» на плате колеса: 147 В есть только при
  включённом колесе, поэтому MEAN WELL выключается вместе с колесом сам.
- Схема упрощена: фара на своём радиореле (кнопка C), обод и бортовая подсветка - каналы
  A и B второго реле; плата колеса управляет только лентой.

## Что дальше

**Свет на колесе**
- Питание от батареи колеса 151 В через MEAN WELL RSDW60H-12 с защитой (предохранитель,
  супрессор, фильтр) - ветка света не трогает штатную фару и стоп.
- Ленты WS2815 12 В: ходовые огни, габариты, педали; радиореле для обода и подсветки;
  драйвер индукционной подсветки обода.
- Гальваническая развязка линии RXD для постоянной установки.

**Следующая прошивка**
- Wi-Fi включается кнопкой в приложении, а не по таймеру; сеть и пароль передаются с
  телефона и хранятся в плате - в прошивке паролей нет. Любая сеть, не только домашняя.
- Обновление плата забирает сама с cjgun.ru, после него Wi-Fi выключается и связь со шлемом
  возвращается.
- Своё имя платы в Bluetooth из приложения; по умолчанию CJ-Wheel-XXXX / CJ-Helmet-XXXX по MAC.

**Шлемы**
- LS2: плата ESP32-C3 вместо ZENGGE на той же ленте - сегменты и пороги как у HJC.
- Своё питание: коробка с аккумулятором 18650, зарядкой и платой на шлеме, стоп на крышке.
- Звук: пьезо-пищалка в шлеме.

**Проверить и поправить**
- Предупреждение по PWM через провод - на живом колесе ещё не видели.
- Дальность Bluetooth в колесе после повышения мощности модуля.
- Работа приложения в фоне, когда телефон в кармане.
- ZENGGE: при возврате эффекта сбивается фон - разбор ответа поправить.

**Потом**
- Мотоцикл: отдельный раздел - датчик света, дополнительный свет, наклон, связь со шлемом.
- Статья о проекте на cjgun.ru.

## Как собрать

- APK: GitHub Actions, workflow «CJ Helmet APK» - на каждую заливку в `shlem`; на метку
  `cj-*` APK уходит в Releases. Подпись своим ключом - секреты HELMET_KS_B64 и HELMET_KS_PASS.
- Прошивка: PlatformIO, платы `nano-c6` и `c3-mini`; пароли Wi-Fi и OTA - в `sekrety.h`,
  который в git не кладётся.
